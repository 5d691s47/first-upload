# 한 끼의 궤적 — BITE / STRIDE

검정 공간 중앙에 놓인 금속 계단형 트레드밀을 직접 조작하는 식사·운동 기록 웹앱입니다. 손의 동작과 기록의 기능을 연결한 인터랙티브 디자인 과제입니다.

## 실행

- `index.html`을 Chrome / Edge / Safari에서 열어 직접 기록할 수 있습니다. 외부 폰트를 내려받지 않습니다. 3D 라이브러리는 프로젝트에 동봉되어 오프라인에서도 작동합니다.
- 기존에 `http://localhost:3000`으로 사용했다면 같은 주소를 유지하세요. Node.js 20 이상에서 `npm start`를 실행합니다.
- Windows에서는 `start.cmd`를 더블 클릭하고 브라우저에서 `http://localhost:3000`으로 접속할 수 있습니다. 설치된 Node 또는 이 컴퓨터의 Codex 번들 Node를 사용합니다.
- 파일 주소, localhost, 127.0.0.1, 포트, 브라우저에 따라 저장 공간이 다릅니다. 원래 사용하던 주소와 브라우저를 유지하세요.
- 계정, 데이터베이스, Vercel 배포가 필요하지 않습니다.

## 하루 칼로리 한도

- 계기판 숫자 또는 오른쪽 위 ‘한도’를 누르면 하루 섭취 한도를 직접 설정할 수 있습니다.
- 설정 전에는 ‘현재 섭취량 / —’, 설정 후에는 예를 들어 ‘125 / 1000’이 표시됩니다. 자동으로 정해진 한도는 없습니다.
- 한도는 매일 같은 값으로 적용되며, 합계는 선택한 날짜에 저장된 식사만 더합니다. 운동 시간은 차감하지 않습니다.
- 식사는 계단에 실제 저장한 뒤 합계에 반영됩니다. 저장 전 준비 상태는 포함하지 않습니다. 수정·삭제·삭제 되돌리기도 계기판에 반영됩니다.
- 한도 초과를 이유로 입력을 막거나 섭취량을 한도까지만 표시하지 않습니다. 입력한 기록의 합계를 그대로 보여줍니다.
- 한도는 기록과 함께 브라우저에 저장하고 JSON 백업에 포함합니다. 이전 버전 백업에 한도가 없어도 불러올 수 있습니다. 기존 한도가 있으면 유지하고, 없으면 백업의 한도를 가져옵니다.
- ‘설정 해제’는 한도만 비우며 식사 기록은 유지합니다. 예시 공간의 한도는 내 기록과 분리되어 있습니다.
- 오늘 화면을 열어 둔 채 날짜가 바뀌면 새 날짜의 합계로 갱신합니다. 과거 날짜를 보고 있다면 해당 날짜를 유지합니다.

## 화면과 조작

첫 화면에는 검정 배경, 금속 계단, 작은 계기판과 최소한의 흰 글씨만 표시합니다. 실시간 3D 크롬 표면에 스튜디오 조명과 반사, 작은 빛 번짐을 표현합니다. 부드럽게 변하는 각도에서 하이라이트가 움직이며 손을 대면 멈춥니다. 기록이 있는 계단 앞면에만 작은 검정 이름판과 흰색 음식·운동 이름을 표시합니다. 빈 계단에는 이름판이 없습니다. 이름판을 짧게 누르면 요약, 길게 누르면 수정이 열립니다. 입력창과 아카이브는 필요한 순간에만 열립니다.

### 기록 / 저장

1. 빈 계단을 약 0.5초간 길게 누릅니다. 누른 자리에 원형 피드백이 나타나고 음식 입력이 열립니다.
2. 음식명, kcal, 시각, 짧은 메모를 입력해 준비합니다. 이때는 아직 저장되지 않습니다.
3. 계단을 아래로 끝까지 밀고 손을 떼면 금속 표면에 한 끼가 새겨지며 저장됩니다.
4. 운동은 계기판의 작은 ↑ 또는 화면 아래 ↑에서 종류·시간을 입력하고, 계단을 위로 밀어 저장합니다.
5. 운동의 눈금이 더해져도 식사 기록과 섭취 kcal는 지워지거나 차감되지 않습니다. 손을 돌린 횟수를 실제 운동량으로 환산하지 않습니다.
6. 짧은 드래그, 반대 방향, 취소된 포인터 동작은 저장하지 않습니다. 준비한 기록의 ×를 누르면 취소합니다.

### 탐색 / 수정

- 계단 한 칸을 마우스로 누른 채 위아래로 끌면 벨트가 그 방향으로 따라 움직입니다. 잡은 상태에서 방향을 바꿀 수 있으며, 화면상의 계단 간격에 맞춰 이동량을 계산합니다.
- 기록이 없어도 빈 계단은 양방향으로 계속 순환합니다. 준비한 기록이 없으면 움직임 자체로 기록이 추가되거나 삭제되지 않습니다.
- 저장된 기록은 같은 날의 벨트를 따라 다시 돌아오며, 화면에 반복 표시되어도 데이터가 중복 저장되지는 않습니다.
- 빠르게 놓으면 관성으로 돌아가며 손을 대면 즉시 멈춥니다. 시스템의 동작 줄이기 설정에서는 관성을 생략합니다.
- 기록을 짧게 누르면 시각·이름·수치가 잠시 표시됩니다. 길게 누르면 내용 확인과 수정이 열립니다.
- 각 날짜에는 새 기록을 위한 빈 계단이 있습니다.

### 삭제 / 복구

- 준비한 기록이 없는 상태에서 저장된 계단을 좌우로 길게 빼낸 뒤 손을 떼면 그 기록만 삭제됩니다.
- 중간에 놓으면 돌아갑니다. 삭제 후 약 8초 동안 나타나는 ‘되돌리기’를 누르면 복구됩니다.
- 상세 화면의 삭제 버튼으로도 확인 후 삭제할 수 있습니다. 삭제 복구는 현재 화면에서만 가능하며, 삭제 후 새로고침하면 되돌리기 상태는 유지되지 않습니다.
- 역회전 운동 저장은 삭제 동작과 구분됩니다.

### 아카이브

- 두 손가락을 벌렸다 놓거나 아래 ↔를 누르면 날짜별 아카이브가 열립니다.
- 날짜 이동·직접 선택, 시간 간격 타임라인, 기록 상세·수정 기능을 제공합니다.
- 타임라인은 가로로 스크롤할 수 있습니다. 식사와 운동은 서로 다른 높이에 표시됩니다.
- 기록 관리(•••)에서 JSON 내보내기·불러오기, 이전 식탁 초안 불러오기를 제공합니다.

### 보조 조작

- 아래 ↓ ↑ ↔ 버튼과 키보드로도 주요 기능을 사용할 수 있습니다.
- 계단에 포커스 후 Enter: 선택한 기록 수정 또는 새 한 끼 입력.
- 방향키: 준비한 기록 확정(식사 ↓ / 운동 ↑), 또는 저장된 기록 탐색.
- Delete: 선택한 기록 삭제 확인. Escape: 준비 취소 또는 요약 닫기.
- ♪: 짧은 기계음 켜기/끄기. 기본은 꺼져 있습니다.
- ?: 사용 방법.

## 기록 유지 / 이전

- 실제 기록은 `localStorage` 키 `bite-stride-diary-v1`을 그대로 사용합니다. 이번 화면 변경으로 저장 형식을 바꾸지 않습니다.
- 같은 브라우저·같은 주소에서 탭을 닫거나 새로고침해도 기록은 유지됩니다.
- 이전 `quokka-diary-v1`의 먹은 음식은 최초 1회 식사 기록으로 옮깁니다. 미확정 식탁 메모는 초안으로 보관하고 이전 키는 지우지 않습니다.
- 날짜만 있던 구형 기록은 해당 날짜 12:00으로 표시하고, 실제 기록 시각이 있으면 사용합니다.
- 사진은 기록에 저장하지 않습니다.
- 브라우저 사이트 데이터 삭제, 시크릿 창 종료, 저장 제한 환경에서는 보존이 보장되지 않습니다. 저장 실패 시 안내하고 내보내기로 보관할 수 있습니다.
- JSON 불러오기는 기존 기록을 유지하고 새 ID만 추가합니다. 동일 ID는 기존 기록을 우선하므로 반복해서 가져와도 중복되지 않습니다.

## 발표 / 예시

- 오른쪽 위 ‘예시’는 최근 3일의 식사·운동 샘플을 보여줍니다. 중앙 위에 EXAMPLE이 표시됩니다.
- 예시의 입력·수정·삭제는 내 기록과 분리되며 새로고침하면 초기화됩니다.
- 개인 기록을 공용 아이패드로 옮기려면 JSON 내보내기 → 해당 기기에서 불러오기를 사용합니다.
- 터치 이벤트와 태블릿 크기는 Chromium에서 검사했습니다. 실제 아이패드 Safari에서의 터치·키보드 동작은 별도 확인이 필요합니다.

## 선택 기능: 음식 사진 분석

입력창의 ‘사진으로 입력하기’에서 촬영/선택 → 전송 동의 → 분석할 수 있습니다. 기존 서버 API를 유지합니다.

- 로컬 Node 서버와 환경 변수 `OPENAI_API_KEY`, `OPENAI_MODEL`이 필요합니다.
- 키는 서버 환경 변수에만 설정하고 HTML, JavaScript, GitHub에 작성하지 마세요.
- 서버/키/모델이 없으면 직접 입력할 수 있습니다. 정적 파일만으로는 사진 분석이 작동하지 않습니다.
- 20MB 이하 사진을 최대 1280px JPEG로 축소합니다. 사진을 바꾸거나 입력창을 닫으면 진행 중 요청이 취소됩니다.
- 실제 AI 요청은 자동 검사하지 않았습니다. 분석값을 확인·수정한 뒤 저장합니다.

## 파일 / 검증

- `index.html`, `style.css`: 전체 화면 장치, 입력창, 아카이브, 접근성 보조 도구.
- `diary.js`: 기록 검증, 이전 기록 변환, 백업 합치기, 예시.
- `sketch.js`: 터치 입력, 관성, 방향별 저장, 가로 삭제·복구, 핀치, UI와 사진 분석. 투영된 3D 계단 위치에 맞춰 터치를 판정합니다.
- `chrome-machine.js`: 크롬 재질, 곡선 손잡이, 스튜디오 환경 반사, 은은한 bloom과 반응형 카메라를 갖춘 WebGL 3D 렌더러.
- `vendor/three.min.js`: Three.js 0.160.1의 로컬 번들. 공식 npm 패키지 무결성과 파일 일치를 확인했습니다. MIT 라이선스는 `vendor/THREE-LICENSE.txt`에 포함합니다.
- WebGL을 사용할 수 없는 환경에서는 기존 Canvas 화면으로 기록 기능을 사용할 수 있습니다. 동작 줄이기 설정에서는 주변의 느린 움직임과 관성을 생략합니다.
- `server.mjs`, `start.cmd`: 기존 로컬 실행 환경.
- `diary.test.mjs`, `server.test.mjs`: `npm test`로 실행.

검사 항목: 식사·운동 독립 보존, 구형 기록 변환, 백업 검증과 중복 방지, 서버 비공개 파일 차단, 길게 눌러 입력·수정, 방향별 저장, 짧은/반대 방향 미저장, 새로고침 유지, 가로 삭제와 복구, 키보드, 실제 두 손가락 이벤트, 날짜별 아카이브, 대화상자 안 삭제·복구, JSON 입출력, 관성과 터치 정지, 예시 격리, 사진 미설정 안내, 휴대폰·태블릿 크기, 파일 직접 실행, 브라우저 오류 없음.

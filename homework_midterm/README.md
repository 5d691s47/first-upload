# 한 끼의 궤적 — BITE / STRIDE

매일 먹은 순간과 움직인 순간을, 서로 다른 방향으로 돌리는 계단에 새기는 인터랙티브 식단·운동 기록 앱입니다.

## 실행

- 화면과 직접 기록은 `index.html`을 Chrome / Edge / Safari에서 열어 바로 사용할 수 있습니다. 외부 폰트나 라이브러리를 내려받지 않습니다.
- 기존에 `http://localhost:3000`에서 사용했다면 같은 주소를 계속 사용하세요. Node.js 20 이상에서 이 폴더를 열고 `npm start`를 실행하면 됩니다.
- Windows에서는 `start.cmd`를 더블 클릭해 로컬 서버를 시작할 수도 있습니다. Node가 설치되어 있거나 이 컴퓨터의 Codex 번들 Node가 있으면 사용합니다. 서버 실행 후 브라우저에서 `http://localhost:3000`으로 접속하세요.
- 파일 주소, localhost, 127.0.0.1, 포트, 다른 브라우저는 각각 저장 공간이 다릅니다. 기존 기록은 원래 사용하던 주소에서 불러오세요.
- 계정, 데이터베이스, Vercel 배포는 필요하지 않습니다.

## 핵심 인터랙션

1. **한 끼 남기기**: 음식명, 칼로리, 아이콘, 시각, 메모를 입력합니다. 준비만 한 상태에서는 저장되지 않습니다. 계단을 아래로 끝까지 밀고 손을 떼면 저장됩니다.
2. **움직임 남기기**: 운동 종류와 실제 시간을 입력합니다. 계단을 위로 밀고 손을 떼면 운동 기록과 청록색 흔적이 추가됩니다. 식사 기록과 섭취 칼로리는 삭제·차감되지 않습니다.
3. **되감기**: 준비한 기록이 없을 때 계단을 위아래로 밀어 같은 날의 과거 기록을 탐색합니다. 칸을 누르면 내용을 확인·수정할 수 있습니다.
4. **펼치기**: 두 손가락을 벌리거나 펼치기 버튼을 누르면 하루 기록을 시간 간격에 따라 펼쳐 봅니다. 오므리면 접힙니다. 가로로 스크롤할 수 있습니다.
5. **보조 조작**: 준비된 기록의 확정 버튼 또는 계단에 포커스 후 방향키/Enter/Space로도 저장할 수 있습니다. 미완성 드래그, 반대 방향, pointercancel은 저장하지 않습니다.
6. **사운드**: 소리 켜짐 버튼을 누른 뒤 기록하면 짧은 기계음이 납니다. 기본은 꺼져 있습니다. 동작 줄이기 설정에서는 저장 애니메이션을 생략합니다.

운동량은 사용자가 입력한 분 단위 기록입니다. 화면에서 손을 많이 돌려도 운동량이 늘지 않습니다. 식사와 운동을 칼로리 상쇄나 건강 점수로 환산하지 않습니다.

## 기록 보관과 이전

- 실제 기록은 이 브라우저의 `localStorage` 키 `bite-stride-diary-v1`에 저장됩니다. 탭을 닫거나 새로고침해도 같은 주소와 브라우저라면 유지됩니다.
- 이전 `quokka-diary-v1`의 먹은 음식은 처음 열 때 식사 기록으로 옮깁니다. 미확정 식탁 메모는 초안으로 보관하며 ‘이전 식탁 메모 불러오기’로 완성할 수 있습니다. 이전 키는 지우지 않습니다.
- 날짜만 있던 이전 기록은 해당 날짜 12:00으로 표시합니다. 실제 기록 시각이 있으면 사용합니다.
- 원본 사진은 저장하지 않습니다.
- 브라우저 사이트 데이터 삭제, 시크릿 창 종료, 저장 제한 환경에서는 유지가 보장되지 않습니다. 자동 저장에 실패하면 안내하고, 내보내기로 보관할 수 있습니다.
- ‘기록 내보내기’는 JSON 백업을 만듭니다. ‘불러오기’는 기존 기록을 유지하고 새 ID만 추가합니다. 같은 백업을 여러 번 불러와도 중복되지 않습니다. 같은 ID의 다른 수정본은 기존 기록을 우선합니다.
- 기록 삭제는 상세 화면에서 별도로 확인해야 실행됩니다. 역회전으로 식사 기록이 삭제되지는 않습니다.

## 발표 / 공용 아이패드

- ‘예시 체험’은 최근 3일의 식사·운동 샘플을 보여줍니다. 화면 상단에 예시 표시가 나타납니다.
- 예시 공간에서도 입력·드래그·수정할 수 있지만 개인 기록과 분리되어 있습니다. 새로고침하면 예시 변경은 초기화됩니다.
- 내 실제 기록을 다른 기기로 옮기려면 JSON 내보내기 → 해당 기기에서 불러오기를 사용합니다.
- 웹에서 열어 시연할 때도 핵심 기능은 정적 파일만으로 작동합니다. 실제 아이패드 Safari 실기기 확인은 별도로 해 주세요.

## 선택 기능: 음식 사진 분석

기존 사진 분석 기능을 유지했습니다. 음식 입력 창의 ‘음식 사진으로 입력 돕기’에서 촬영/선택 → 전송 동의 → 분석을 진행합니다. 사진은 최대 1280px JPEG로 축소하며 20MB 이하 파일을 받습니다. 사진 변경이나 창 닫기는 진행 중 분석을 취소합니다.

- 사진 분석은 로컬 Node 서버와 환경 변수 `OPENAI_API_KEY`, `OPENAI_MODEL`이 필요합니다. 기존과 동일합니다.
- 키는 서버 환경 변수로만 설정하고 HTML, JavaScript, GitHub에 작성하지 마세요.
- 서버/키/모델이 없으면 직접 입력할 수 있습니다. 정적 호스팅만으로 사진 분석이 동작하지 않습니다.
- 실제 AI 호출은 자동 검사에 포함하지 않습니다. 분석값은 추정치이므로 수정 후 기록합니다.

## 파일

- `index.html`: 화면, 입력 창, 사용 안내
- `style.css`: 데스크톱 / 태블릿 / 모바일 레이아웃
- `diary.js`: 저장 문서 검증, 이전 기록 변환, 백업 합치기, 예시 기록
- `sketch.js`: Canvas 계단, 포인터·핀치 조작, 기록 UI, 선택적 사진 분석
- `server.mjs`: 로컬 정적 서버와 기존 사진 분석 API
- `diary.test.mjs`, `server.test.mjs`: 기록 무결성과 서버 검사
- `start.cmd`: Windows 로컬 실행 도우미
